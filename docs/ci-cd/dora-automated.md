## Методика та можливі розбіжності з ручним підрахунком

- Скрипт використовує часові мітки GitHub REST API в UTC; у `metrics-raw.md` час показано за Києвом. Перехід UTC ↔ EET/EEST може змінювати відображення дати/години, але не тривалість.
- Для часу завершення береться максимальний `completed_at` серед jobs, а не `updated_at` самого workflow run.
- Черга — від створення запуску до старту першого job; виконання — від старту першого до завершення останнього job. Це wall-clock інтервали, а не сума тривалостей усіх jobs.
- Час виконання зміни прив'язується до PR, асоційованого з SHA запуску; початок — найраніший `commit.author.date` у PR. Це може відрізнятися від ручного зіставлення merge-комітів або `authoredDate` у зведеній таблиці.
- Для червоного запуску час виконання зміни завершується наступним зеленим запуском на `main`; час відновлення рахується окремо від завершення червоного до завершення наступного зеленого.
- Якщо API не повернув пов'язаний PR або коміти PR, такий запуск не входить у вибірку часу виконання зміни; кількість пропусків наведена нижче.
- Частота розгортань є наближенням: рахується зелений CI на `main`, а не незалежно підтверджена подія деплою Render/Pages.
