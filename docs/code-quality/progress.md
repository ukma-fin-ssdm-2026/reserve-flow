## 2. Як запустити прототип

Для локального запуску застосунку, бази даних та тестів виконайте наступні кроки:

### 2.1. Підготовка середовища та запуск БД
```bash
# Клонування репозиторію
git clone [https://github.com/ukma-fin-ssdm-2026/reserve-flow.git](https://github.com/ukma-fin-ssdm-2026/reserve-flow.git)
cd reserve-flow

# Встановлення залежностей (продукт + розробка)
pip install -r requirements.txt
pip install -r requirements-dev.txt

# Запуск бази даних через Docker
docker-compose up -d db

# Заповнення бази тестовими даними (Seed)
python src/api/seed.py

# Запуск FastAPI сервера через uvicorn
uvicorn main:app --app-dir src/api --reload

# Запуск пакета тестів через pytest (із перевіркою БД на SQLite/Postgres)
pytest tests/

# Форматування коду
black src/ tests/

# Статичний аналіз лінтером
flake8 src/ tests/

# Сканування безпеки
bandit -c pyproject.toml -r src/ -ll

```

## 3. План до Лабораторної 6: «Тестування та налагодження

Для успішного виконання Лабораторної 6 команда розподілила завдання та сформувала такий план робіт:

1. **Модульні тести та покриття (Керівник тестування / Керівник дублерів):**
   - Написати мінімум 10 додаткових ізольованих модульних тестів для щонайменше 2 ключових модулів (`booking_engine` та `slots`), активно використовуючи фікстури, моки та тестові дублери для обробки граничних випадків (AAA шаблон).
   - Налаштувати звіт покриття (`pytest --cov` з генерацією `htmlcov/`).
   
2. **Челендж з налагодження (Керівник налагодження):**
   - Ввести навмисну логічну помилку в один із модулів, відтворити збій через тест, застосувати систематичне налагодження (симптоми, діагностика, виправлення) та задокументувати процес у новому файлі `/docs/testing/debugging-log.md`.
   
3. **Індивідуальні мікро-цикли TDD (Кожен учасник):**
   - Реалізувати невелику нову функціональність (~20 рядків) через класичний цикл **Red → Green → Refactor** тривалістю 2–3 хвилини на ітерацію.
   - Зафіксувати процес у вигляді детальної історії комітів із тегами `[RED]`, `[GREEN]`, `[REFACTOR]` та записати коротке відео Loom (≤ 5 хв).
   
4. **Документ стратегії тестування (Стратег тестування):**
   - Створити односторінковий документ `/docs/testing/testing-strategy.md`, що описує поточний статус тестування, підсумок покриття, плани для інтеграційних/системних тестів та інтеграцію воріт покриття у конвеєр CI/CD.
   
5. **Бонусні завдання (За бажанням команди):**
   - Реалізувати мутаційне тестування (`mutmut`) або тести на основі властивостей (`Hypothesis`), а також додати ворота покриття в GitHub Actions (`--cov-fail-under`).

## 4. Відповідність стандартам якості

Згідно з інженерними практиками проєкту, весь код перед злиттям проходить перевірку на відповідність критеріям якості та безпеки, описаним у документації [Статичний аналіз коду та лінтери](../docs/code-quality/static-analysis.md). 

Основні інструменти автоматизованого контролю:
- **Black**: забезпечення єдиного стандарту форматування коду.
- **Flake8**: перевірка стилю коду та наявності синтаксичних/логічних помилок.
- **Bandit & detect-secrets**: виявлення вразливостей безпеки та захист від витоку конфіденційних даних.
