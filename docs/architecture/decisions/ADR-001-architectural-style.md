# ADR 001: Вибір архітектурного стилю

**Статус:** Затверджено
**Дата:** 30 вересня 2026
**Учасники:** Team 3

## Контекст
Проєкт Reserve Flow потребує надійної архітектури для управління бронюванням приміщень. Система повинна обробляти інтенсивні транзакції з базою даних, розмежовувати права доступу та підтримувати асинхронні процеси. Команда розглядала мікросервісний підхід та моноліт. Важливо забезпечити плавний користувацький інтерфейс і зберегти легкість розгортання та підтримки для команди з 4 осіб.

## Рішення
Ми обрали **Модульний моноліт (Modular Monolith) на бекенді із відокремленим Single Page Application (SPA) на фронтенді**. 

Система складатиметься з таких частин:
1. **Frontend (SPA):** Відокремлений вебклієнт, який завантажується один раз і спілкується з сервером через REST API.
2. **Backend (Modular Monolith):** Єдиний розгорнутий сервіс, внутрішня структура якого строго розділена на незалежні доменні модулі (Управління користувачами, Бронювання, Сповіщення).
3. **Database:** Єдина реляційна база даних, де кожен модуль працює лише зі своїми таблицями.

## Обґрунтування
- **Відповідність масштабу:** Мікросервіси є надлишковими для вебсервісу такого розміру. Моноліт значно спрощує розгортання (CI/CD) та тестування.
- **Організація коду:** Модульна структура бекенду запобігає перетворенню моноліту на "спагеті-код". Це дозволяє паралельно працювати над різними фічами.
- **UX:** Використання SPA забезпечує швидкий та динамічний інтерфейс користувача без перезавантаження сторінок.

## Наслідки
- **Позитивні:** Низький поріг входу, простота інфраструктури, чіткі межі між компонентами системи.
- **Ризики:** Необхідність суворо дотримуватися дисципліни при написанні коду, щоб модулі на бекенді не перепліталися між собою (вирішується через Code Review).
